# 无人机、地面机器人与中枢通信协议规范（第一优先）

> 这份文档是整个 Internet 模块**最优先要读懂、定死、跑通**的内容。设备怎么
> 配无线网络是后面的活，先保证三方说话用的是同一套语言：哪个设备、用什么
> 协议、连哪个端口、发什么格式的数据。
>
> 新手建议先看 1~3 节，能说出"无人机到中枢走 MAVLink + RTSP，中枢到机器人走
> HTTP JSON"，再往下看消息格式和验收。

## 1. 一张图看懂三台设备怎么说话

```text
无人机 F450 V6C
  │
  │ MAVLink / UDP（位置、姿态、电量、模式）
  │   目标端口：中枢 14550（QGC 用 8080）
  ├──────────────────────────────▶ 中枢地面站 192.168.1.100
  │
  │ RTSP / TCP（机载画面）
  │   地址：rtsp://192.168.1.10:554/...
  └──────────────────────────────▶ 中枢地面站 192.168.1.100

中枢地面站 192.168.1.100
  │
  │ HTTP JSON / TCP（任务下发）
  │   POST http://192.168.1.101:5000/task
  └──────────────────────────────▶ 地面机器人 192.168.1.101

地面机器人 192.168.1.101
  │
  │ HTTP JSON / TCP（状态回传）
  │   GET http://192.168.1.101:5000/status
  └──────────────────────────────▶ 中枢地面站 192.168.1.100
```

一句话总结：

- 无人机 → 中枢：**MAVLink（UDP）传状态，RTSP（TCP）传画面**；
- 中枢 → 地面机器人：**HTTP + JSON（TCP）下发任务**；
- 地面机器人 → 中枢：**HTTP + JSON（TCP）回传状态**。

## 2. 端口规范（先背这张表）

| 链路 | 协议 | 端口    | 谁监听 | 用途 |
|------|------|-------|--------|------|
| 无人机 → 中枢（数传） | UDP | 14550 | 中枢地面站 pymavlink | 读 MAVLink 位姿/状态 |
| 无人机 → 中枢（数传） | UDP | 8080  | 中枢地面站 QGC | 地面站软件显示无人机状态 |
| 无人机 → 中枢（图传） | TCP | 554   | 无人机摄像头 | RTSP 拉取机载画面 |
| 中枢 → 地面机器人 | TCP | 5000  | 地面机器人 task_server | `POST /task` 下发任务 |
| 地面机器人 → 中枢 | TCP | 5000  | 地面机器人 task_server | `GET /status`、`GET /video.mjpeg` |
| 中枢统一仪表盘 | TCP | 20000 | 中枢地面站 Flask | 网页查看无人机/机器人/模型 |
| 无人机独立仪表盘 | TCP | 20001 | 无人机端 | 本机调试页面 |
| 地面机器人独立仪表盘 | TCP | 20002 | 地面机器人 | 机器人调试页面 |
| YOLO 检测 API（按需） | TCP | 8000  | 中枢地面站 | 远程调用 `/detect` |
| 视频流 UDP 转发（按需） | UDP | 5000  | 中枢地面站 GStreamer | 与机器人 TCP 5000 同号不同协议 |
| 视频二次转发（按需） | TCP | 8554  | 中枢地面站 MediaMTX | 多路拉流 |
| 远程调试 | TCP | 22    | 各设备 | SSH，仅内网/VPN |

> 特别注意两个"5000"：
>
> - `TCP 5000`：机器人对外服务，跑在树莓派上；
> - `UDP 5000`：GStreamer 视频流转发，跑在中枢地面站。
>
> 协议不同、设备不同，理论上不冲突，但联调容易混淆。完整出处见
> [../端口清单.md](../端口清单.md)。

## 3. 无人机 ↔ 中枢：用什么协议通信

### 3.1 数传：MAVLink over UDP

无人机和中枢之间的"状态数据"走 **MAVLink 协议**，底层是 **UDP**。MAVLink 是
飞控与地面站之间的标准消息协议，本项目不再用 ROS/MAVROS，而是用 Python 的
**pymavlink** 直接读消息。

连接串（中枢端执行）：

```text
udpin:0.0.0.0:14550
```

关键消息：

| MAVLink 消息 | 拿到的信息 | 怎么用 |
|--------------|-----------|--------|
| `HEARTBEAT` | 在线、飞行模式、是否解锁 | 超时 15 秒算离线 |
| `LOCAL_POSITION_NED` | 局部坐标（北-东-下） | 转 ENU 后算目标坐标 |
| `GLOBAL_POSITION_INT` | GPS 经纬高 | 目标全局坐标 |
| `ATTITUDE` | 姿态 | 偏航角、坐标旋转 |
| `SYS_STATUS` | 电压、剩余电量 | 电量监控 |

端口规则：

- QGC 监听 **UDP 8080**；
- pymavlink 监听 **UDP 14550**；
- 两个程序不能同时占同一个 UDP 端口，所以端口要错开；
- 若数传只把数据发往一个目标，需要在数传/飞控端把地面站 IP 和端口加为额外
  目标，或让 pymavlink 与 QGC 共用同一路串口数据。

最小读取命令（Windows）：

```bat
python D:\yolo\scripts\read_drone.py
```

教学与排查见 [../Dron/教学/MAVLink与MAVROS.md](../Dron/教学/MAVLink与MAVROS.md)
和 [../Dron/开始配置.md](../Dron/开始配置.md)。

### 3.2 图传：RTSP over TCP

无人机机载摄像头画面走 **RTSP 协议**，底层是 **TCP**，默认端口 **554**。
中枢地面站用 OpenCV、QGC 或 ffmpeg 拉流：

```text
rtsp://192.168.1.10:554/user=admin&password=&channel=1&stream=1.sdp?
```

地址含义：

| 部分 | 含义 |
|------|------|
| `192.168.1.10` | 无人机图传摄像头 IP |
| `554` | RTSP 默认端口 |
| `channel=1` | 第 1 路视频 |
| `stream=1` | 码流 1 |

教学与排查见 [../Dron/教学/机载视觉与视频流.md](../Dron/教学/机载视觉与视频流.md)。

## 4. 中枢 ↔ 地面机器人：HTTP + JSON

### 4.1 任务下发

中枢地面站向机器人发任务：

```http
POST http://192.168.1.101:5000/task HTTP/1.1
Content-Type: application/json
```

```json
{
  "task_id": "T20260823-001",
  "time": 1780000000.0,
  "cmd": "PICK",
  "target": {
    "x": 12.5,
    "y": 8.3,
    "heading_deg": 0.0,
    "confidence": 0.87,
    "source": "drone_yolo"
  },
  "arrive_radius": 0.8
}
```

字段约定：

| 字段 | 类型 | 说明 |
|------|------|------|
| `task_id` | string | 全链路唯一，格式 `TYYYYMMDD-NNN` |
| `time` | number | Unix 秒 |
| `cmd` | string | 当前默认 `PICK`，预留 `RIGHT/LEFT/FORWARD/HOLD` |
| `target.x` / `target.y` | number | 目标局部坐标，单位米，ENU 方向 |
| `target.heading_deg` | number | 建议朝向，单位度 |
| `target.confidence` | number | 检测置信度 0~1 |
| `target.source` | string | `drone_yolo`、`robot_yolo`、`manual` |
| `arrive_radius` | number | 机器人判定到达半径，单位米 |

机器人返回：

```json
{"task_id": "T20260823-001", "status": "accepted"}
{"task_id": "T20260823-001", "status": "done", "picked": true}
{"task_id": "T20260823-001", "status": "failed", "reason": "target_lost"}
```

状态流转：`accepted` → `executing` → `done` / `failed`。`failed` 必须带
`reason`，统一用小写下划线命名（如 `target_lost`、`out_of_reach`、
`grip_failed`）。

### 4.2 状态回传

机器人主动提供状态查询接口：

```http
GET http://192.168.1.101:5000/status HTTP/1.1
```

返回示例：

```json
{
  "online": true,
  "state": "NAV",
  "position_m": {"x": 0.0, "y": 0.0},
  "heading_deg": 0.0,
  "picked_count": 0,
  "last_task": "T20260823-001",
  "last_result": "done",
  "message": "等待地面站下发任务"
}
```

`state` 至少覆盖：`NAV`、`SEARCH`、`APPROACH`、`PICK`。中枢仪表盘按 1~2 秒
轮询一次，不作为高实时控制通道。

### 4.3 机器人画面

```http
GET http://192.168.1.101:5000/video.mjpeg HTTP/1.1
```

该接口返回 MJPEG 流，供机器人调试页面或中枢仪表盘预览。

## 5. 协议通用规则

1. 所有 HTTP JSON 接口必须带 `Content-Type: application/json`；
2. 坐标单位统一为**米**，朝向统一为**度**，时间统一为 Unix 秒；
3. `task_id` 全链路唯一，机器人对重复 `task_id` 做幂等处理；
4. 中枢调用机器人接口：超时 5 秒，失败重试 3 次，间隔 1 秒；
5. 机器人状态轮询间隔 1~2 秒，`online=false` 或超时视为离线；
6. 视频延迟只在**本地局域网**按 <200ms 验收；
7. 控制类端口（机器人 5000、SSH 22）默认只在内网开放。

## 6. 新手跑通顺序

```bat
:: 1. 先 ping 通三方
ping 192.168.1.101
ping 192.168.1.123
ping 192.168.1.10

:: 2. 查机器人状态
curl http://192.168.1.101:5000/status

:: 3. 下发一次任务
curl -X POST http://192.168.1.101:5000/task ^
  -H "Content-Type: application/json" ^
  -d "{\"task_id\":\"T999\",\"target\":{\"x\":0.0,\"y\":0.0}}"
```

```bat
:: 4. 读无人机 MAVLink（前提是 read_drone.py 已按 GroundStation/开始配置.md 配好）
python D:\yolo\scripts\read_drone.py
```

## 7. 协议验收清单

| 检查项 | 达标 |
|--------|------|
| 无人机数传 | pymavlink 或 QGC 能读到 `HEARTBEAT` |
| 无人机位姿 | `LOCAL_POSITION_NED` / `GLOBAL_POSITION_INT` 能打印 |
| 无人机图传 | RTSP 能拉到画面 |
| 任务下发 | `POST /task` 返回 `accepted` |
| 状态回传 | `GET /status` 返回 JSON，状态字段正确 |
| 中枢仪表盘 | `http://192.168.1.100:20001` 能看到三类信息 |
| 全流程 | 本地局域网视频延迟 <200ms，全流程 <5 分钟 |

## 8. 常见问题

| 现象 | 排查 |
|------|------|
| pymavlink 收不到心跳 | 端口 14550 与 QGC 8080 互斥；数传目标 IP 未加地面站 |
| RTSP 拉不到 | 摄像头 IP/密码、554 端口、码流通道参数 |
| 机器人 `POST /task` 不返回 accepted | 先查 `GET /status`；确认 `autonomous_pick.py` 已启动、5000 端口已监听 |
| 机器人显示离线 | 确认机器人 STA 模式；`hostname -I` 是否是 `192.168.1.101` |
| 端口 5000 混淆 | TCP 5000 是机器人服务，UDP 5000 是视频转发，分开排查 |
