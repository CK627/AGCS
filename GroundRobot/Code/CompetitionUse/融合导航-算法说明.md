## 一、一句话概括

> **相机负责「写状态」（告诉我歪了多少、偏了多少），IMU 负责「执行」（走路、转弯），
> 中间用一个从不归零的状态量 `(航向误差 e, 横向偏差 cross)` 做唯一的交流通道。**

以前是两个回路各管各的：IMU 管航向（转弯），颜色管横向（平移）。结果是「先直、然后一路偏出去」，IMU 数值还乱跳。融合导航把它们改成**一个卡尔曼滤波器 + 一个单一控制器**，从根上消除打架。

---

## 二、先讲清楚「为什么会打架」（问题的本质）

这是整个算法存在的前提，值得说透。

### 2.1 相机装在机身上，画面分不清「转」还是「移」

机身转了 e 度，画面里的色块会横移 `f·tan(e)` 像素；机器人横移了 d 毫米，画面里的色块也横移。**这两件事在画面上看起来一模一样**，单看一张图根本分不开。

### 2.2 平移修不掉航向

真实链路是：航向歪了 → 色块在画面里偏了 → 程序发「平移」去把色块拉回中间 → 但航向没变 → 往前走一段又偏出去 → 再平移……机器人走的是**斜线**，航向误差从头到尾躺在那里没被处理过。这就是现场看到的「先直、然后一路偏出去」。

### 2.3 横向平移不是纯平移，会踢航向

六足 crab 横移一步，基本都会带动一下航向。于是颜色回路在往 IMU 回路里注入扰动，IMU 再转回来，两个回路**对打**。日志上就表现为「IMU 数值乱」。

### 2.4 为什么「纠偏后 reset IMU」治标不治本

单次方位观测只给出 **1 个约束**，却要解 **2 个未知数**（航向误差 e、横向偏差 cross）：

```
β = atan2(−cross, R) − e
```

能把这俩分开的是**时间**：机器人往前走，距离 R 变小，β 对 cross 的敏感度上升、对 e 的敏感度不变——正是这段「边走边看」的过程，才把两个状态慢慢分开。

而旧的 `tracker.reset()` 每转一次弯就把 e 的积分清零，等于把好不容易攒下来的「可观测性」丢掉；相机那边又同时重取基准。**两个绝对参考同时归零**，系统从此再没有任何东西知道「我到底歪了多少」。

> 一句话：**reset 不是让误差消失，是把误差从 `yaw` 这个数字里，搬进了机器人的真实姿态里。数字干净了，机器人歪了。**

## 三、融合的整体结构

把 IMU 当**预测**（短期准、长期漂），把相机当**观测**（绝对、慢、会丢帧），两者只通过一个**不归零的状态** `(e, cross)` 交流：

```
IMU Δθ  ──► 预测 ──┐
                     ├─► 融合状态 (e, cross) ──► 单一控制器（先航向后横向）
相机 β  ──► 观测 ──┘
```

规则就一条：**相机写状态，IMU 管执行。** 谁也不去「消掉对方造成的结果」。
bias（零漂）标定照做——那是传感器属性；但**状态永不清零**。

### 坐标系约定（贯穿全文）

| 符号 | 含义 | 单位 | 方向 |
|------|------|------|------|
| `e` | 相对本段标称航向的偏差 | 度 | 右正 |
| `cross` | 相对标称中心线的横向偏差 | 毫米 | 右正 |
| `β` | 色块相对相机光轴的方位角 | 度 | 右正，`β = atan((cx − cx0) / f_px)` |
| `R` | 到色块的前向距离 | 毫米 | — |

## 四、核心算法：两状态卡尔曼融合（`heading_fusion.py`）

### 4.1 状态量

```python
self.e = 0.0        # 航向误差估计（度，右正）
self.cross = 0.0    # 横向偏差估计（mm，右正）
self.p00 = 4.0      # 协方差，初值偏大 = 一开始更信任相机
self.p01 = 0.0
self.p10 = 0.0
self.p11 = 400.0
self.updates = 0    # 收到过多少次相机观测
```

### 4.2 预测（IMU 管这一段）

每走一小段，把「IMU 测到的航向增量」和「本段前进距离」推进状态：

```python
def predict(self, d_theta_deg, ds_mm=0.0, lateral_mm=0.0):
    self.e += float(d_theta_deg)
    # 航向误差 → 横向漂移：这是「不纠航向就一定会偏出去」的数学来源
    self.cross += float(ds_mm) * math.sin(self.e * _DEG) + float(lateral_mm)
    if self.cross > self.cross_limit:
        self.cross = self.cross_limit
    elif self.cross < -self.cross_limit:
        self.cross = -self.cross_limit

    # 雅可比 F = [[1, 0], [a, 1]]，a = ∂cross/∂e（mm/deg）
    a = float(ds_mm) * math.cos(self.e * _DEG) * _DEG
    p00, p01, p10, p11 = self.p00, self.p01, self.p10, self.p11
    self.p00 = p00
    self.p01 = p00 * a + p01
    self.p10 = a * p00 + p10
    self.p11 = (a * p00 + p10) * a + (a * p01 + p11)
    self.p01 = self.p10 = (self.p01 + self.p10) * 0.5   # 对称化，防数值漂移

    self.p00 += self.q_head
    self.p11 += self.q_cross
```

**白话**：`e` 直接累加 IMU 转角；`cross` 累加 `ds·sin(e)`——意思是「航向歪了 e，往前走 ds 就会横漂 ds·sin(e)」。这就是「不纠航向，走直线也一定偏」的数学来源。协方差 P 用雅可比 F 往前传一步，再叠上过程噪声 q（q 越大 = 越不信任 IMU 的长期精度、越信任相机）。

### 4.3 观测更新（相机管这一段）

看到色块时，用它的像素横坐标算方位角 β，做一次观测：

```python
def update_bearing_deg(self, beta_deg, range_mm):
    r = float(range_mm)
    # h = atan2(-cross, R) - e ：用「当前估计」预测色块应该出现在哪个方位
    h = math.atan2(-self.cross, r) * _RAD - self.e
    y = (float(beta_deg) - h + 180.0) % 360.0 - 180.0   # 残差

    # 雅可比 H = [∂h/∂e, ∂h/∂cross] = [-1, -R/(cross²+R²)·(180/π)]
    h0 = -1.0
    h1 = -r / (self.cross * self.cross + r * r) * _RAD

    p00, p01, p10, p11 = self.p00, self.p01, self.p10, self.p11
    ph0 = p00 * h0 + p01 * h1      # (P Hᵀ)[0]
    ph1 = p10 * h0 + p11 * h1      # (P Hᵀ)[1]
    s = h0 * ph0 + h1 * ph1 + self.r_beta
    if s <= 1e-9:
        return y
    k0 = ph0 / s
    k1 = ph1 / s

    self.e += k0 * y
    self.cross += k1 * y
    # ... 协方差更新（标准卡尔曼 P = (I - KH)P）...
    self.updates += 1
    return y
```

**白话**：模型 `h = atan2(−cross, R) − e` 说的是「如果我的航向误差是 e、横向偏差是 cross，那色块应该在方位 h」。实测方位 β 和 h 的差就是**残差 y**（我估计错在哪）。卡尔曼增益 K 按「观测准不准」把 y 加权摊到 e 和 cross 上。注意 H 里 `h1 = −R/(cross²+R²)`：**R 越小（越接近方块），方位角对 cross 越敏感**——这正是靠「边走边看」把两个状态分开的关键，也是第三节说的「时间」。

## 五、单一控制器：先航向、后横向（`LaneController`）

```python
def decide(self, e_deg, cross_mm):
    if abs(e_deg) > self.head_deadzone:
        turn = -self.head_gain * e_deg          # 朝右歪（e>0）→ 左转（负）
        turn = max(-self.head_max, min(self.head_max, turn))
        if abs(turn) < 1.0:
            turn = math.copysign(1.0, turn)     # 最小步进，攒着
        self.last_action = 'turn'
        return turn, 0.0

    if abs(cross_mm) > self.cross_deadzone:
        lat = -self.cross_gain * cross_mm       # 偏右（cross>0）→ 左移（负）
        lat = max(-self.cross_max, min(self.cross_max, lat))
        if abs(lat) < 3.0:
            lat = math.copysign(3.0, lat)
        self.last_action = 'lateral'
        return 0.0, lat

    self.last_action = 'none'
    return 0.0, 0.0
```

**白话**：这就是解耦的另一半。原来两个回路各盯各的误差、各走各的通道；现在**同一个小块里只发一种指令**——航向没进死区就只转，进了死区才横移。逻辑是：航向误差是横向误差的**因**，因没除掉之前不动果。返回的 `(turn_deg, lateral_mm)` 至多一个非零。

## 六、直线段主循环（`1.py` 的 `move_straight_fusion`）

这是把上面两半拼起来、真正「边走边看」的地方：

```python
def move_straight_fusion(ik, board, detector, imu_state, tracker, distance_mm,
                         fusion, ctrl, marker_range_mm, marker_size_mm, cam_state,
                         color_enabled=True):
    remaining = abs(int(distance_mm))
    forward = distance_mm >= 0
    while remaining > 0:
        det = detector() if color_enabled else None
        cx = None
        if det is not None:
            cx = det.get('bbox_center_x', det['center'][0])
            # 相机俯仰跟踪：方块快出画面底部就往下压 24，保证参照不丢
            cy = det['center'][1]
            if cy > CAM_TRACK_CY_LOW and cam_state['pulse'] > CAM_TRACK_MIN_24:
                cam_state['pulse'] = max(CAM_TRACK_MIN_24, cam_state['pulse'] - CAM_TRACK_STEP)
                board.bus_servo_set_position(0.15, [[24, cam_state['pulse']]])
            elif cy < CAM_TRACK_CY_HIGH and cam_state['pulse'] < CAM_TRACK_MAX_24:
                cam_state['pulse'] = min(CAM_TRACK_MAX_24, cam_state['pulse'] + CAM_TRACK_STEP)
                board.bus_servo_set_position(0.15, [[24, cam_state['pulse']]])
            if marker_size_mm > 0 and det.get('radius'):
                r = range_from_radius_px(det['radius'], marker_size_mm, FUSION_F_PX_FULL)
                if r is not None:
                    marker_range_mm = max(80.0, r)
        if cx is not None:
            if not isinstance(fusion, ReferenceFusion) and fusion.updates == 0:
                fusion.cx0 = cx                     # LaneFusion 旧行为：冻住初始像素当基准
                print('融合基准 cx0 → %.1f（色块初始像素）' % cx, flush=True)
            fusion.update_bearing(cx, marker_range_mm)   # ← 相机写状态

        turn, lateral = ctrl.decide(fusion.heading_error, fusion.cross_error)
        if turn != 0.0:
            if turn < 0:
                ik.turn_left(ik.initial_pos, 2, abs(turn), TURN_SPEED, 1)
            else:
                ik.turn_right(ik.initial_pos, 2, abs(turn), TURN_SPEED, 1)
            print('融合 e=%+.2f° cross=%+.0fmm -> 转%+.1f°'
                  % (fusion.heading_error, fusion.cross_error, turn), flush=True)
        elif lateral != 0.0:
            if lateral < 0:
                ik.left_move(ik.initial_pos, 2, abs(lateral), MOVE_SPEED, 1)
            else:
                ik.right_move(ik.initial_pos, 2, abs(lateral), MOVE_SPEED, 1)
            print('融合 e=%+.2f° cross=%+.0fmm -> 横移%+.0fmm'
                  % (fusion.heading_error, fusion.cross_error, lateral), flush=True)

        # IMU 增量：since_last 给的是「自上次调用以来」的平均角速度与时长
        rate, dt = tracker.since_last()
        d_theta_right = -rate * dt                  # imu_state['yaw'] 左正 → 本模块右正取负
        move = min(100, remaining)                  # 100mm 一小块，小步闭环
        fusion.predict(d_theta_right, ds_mm=(move if forward else -move),
                       lateral_mm=lateral)
        move_one_chunk(ik, move, forward)
        remaining -= move
        time.sleep(0.05)
    return marker_range_mm
```

**白话**（一个小块循环的完整流程）：

1. **看一眼**（相机写状态）：检测色块 → 拿到像素横坐标 cx → `update_bearing` 更新 `(e, cross)`；顺便用视半径反推距离、用 24 号俯仰跟踪把方块压在画面里。
2. **决定动作**（单一控制器）：`decide(e, cross)` 只返回一种——先转航向，进了死区再横移。
3. **执行**：发舵机/步态指令。
4. **推一步**（IMU 管执行）：把本小块 IMU 实测转角喂进 `predict`，往前走 100mm，进入下一个小块。

关键设计都在细节里：

- **距离切 100mm 小步**：每步都重新「看 + 纠」，闭环频率高，误差不累积。
- **状态不归零**：`fusion` 全程不 reset，残差一直累在 e/cross 上（参考系不丢）。
- **俯仰跟踪**：接近时方块会往画面底部掉，24 号往下压把它留在画面里，融合才不丢参照。
- **`color_enabled=False`**：弯道里关颜色（那段只靠 IMU 走），长直行（≥400mm）才重新开——避免弯道里的误检测把融合带偏。

## 七、转弯怎么接（`feed_turn_to_fusion`）

直线和转弯是两种模式，切换处最容易出 bug。关键在「转弯本身不该被当成漂移」：

```python
def feed_turn_to_fusion(imu_state, tracker, fusion, yaw_before, cmd_right_deg):
    d_yaw_left = imu_state['yaw'] - yaw_before
    residual = -d_yaw_left - cmd_right_deg      # 右正：实际 − 命令
    if isinstance(fusion, ReferenceFusion):
        # 方块位置按「命令转角」推进，e 只累积残差 —— 方块参照系不跟着转弯残差歪掉
        fusion.predict(residual, ds_mm=0.0, d_theta_cmd_deg=cmd_right_deg)
    else:
        fusion.predict(residual, ds_mm=0.0)
        # LaneFusion 用冻结的 cx0 当基准，转弯后方块相对机身的方位变了，把 cx0 转过去
        fusion.rotate_reference(-cmd_right_deg)
    tracker.since_last()   # 把 since_last 的基准挪到「此刻」
    print('转弯残差 %+.2f°（IMU 实测 %+.2f° / 命令 %+.1f°）-> e=%+.2f°'
          % (residual, -d_yaw_left, cmd_right_deg, fusion.heading_error), flush=True)
    return residual
```

**白话**：命令转 90°，IMU 实测转了 91°，那多出来的 1° 才是「残差」，才该累进 e。转弯本身（那 90°）**不能**灌进 e，否则 e 会被撑爆、机器人以为自己在漂移。转弯残差才是相机应该看到并修掉的东西。之后 `reset_imu(..., reset_yaw=False)`：零漂重标（传感器属性），但 yaw 不清零（状态不能丢）。

## 八、两种融合方案：Lane vs Reference

`1.py` 用 `--fusion lane|reference` 切换，默认 `lane`。两者的卡尔曼状态 `(e, cross)` **完全相同**，区别只在**观测基准**：

| | LaneFusion（A，默认） | ReferenceFusion（B，试验） |
|---|---|---|
| 方块怎么定位 | 把初始方位冻成 `cx0`，方块「应正对机身」 | 跟踪方块在理想路线里的位置 `(bx, by)` |
| 前进时 | 方块应有的方位变化被当成漂移 → 机器人被「吸」向方块 | 把「应有的方位变化」从观测里扣掉 → 照路线走，方块只纠漂移 |
| 转弯后 | `rotate_reference` 把 cx0 转过去 | `predict` 用「命令转角」推进 `(bx,by)` |
| 现场表现 | 稳定 | 上一版发散过（e 飙到 −142°），这一版改成卡尔曼平滑 + 创新门限 |

**ReferenceFusion 多出来的 `(bx, by)` 是确定性的方块位置预测，不进卡尔曼状态**，只是用来算「方块应有的方位 β_ref」，再从实测里扣掉。它加了两个防发散的门限：

```python
# 方块太近（by 太小）时，atan2(bx,by) 对误差极敏感，观测不可靠，跳过
if self.by < self.min_ahead_mm:
    return self.e, self.cross

beta_meas = math.atan((cx_px - self.cx0) / self.f_px) * _RAD
beta_ref  = math.atan2(self.bx, self.by) * _RAD
beta_rel  = (beta_meas - beta_ref + 180.0) % 360.0 - 180.0

# 创新门限：单次观测残差超阈值当野值丢掉
if abs(y) > self.max_innov_deg:
    return self.e, self.cross
```

## 九、IMU 为什么必须「密集采样」（`init_imu`）

这是融合的**数据地基**，没有它上面的卡尔曼全是空中楼阁：

```python
def init_imu(board):
    board.enable_reception()
    state = {'bias': 0.0, 'yaw': 0.0, 'last_rate': 0.0, 'last_dt': 0.0}
    tracker = ImuTracker(board, state,
                         scale_left=GYRO_SCALE_LEFT, scale_right=GYRO_SCALE_RIGHT)
    tracker.start()                       # 后台线程，约 105Hz 连续积分
    time.sleep(0.5)
    bias, n = tracker.calibrate(1.0, settle=0.0)   # 开机静止，标 gz 零漂
    tracker.reset()
    state['tracker'] = tracker
    return state
```

**白话**：官方 SDK 的 `imu_queue` 是 `maxsize=1` 且满了就丢，`get_imu()` 只能拿到「上次取走之后到达的第一个样本」——**两次调用之间的样本全丢**。所以绝不能「要用的时候读一个样本」再乘上一段多秒的 dt，那会灌进随机方向的假转角。解法是让 `ImuTracker` 后台线程 **~105Hz 连续采样积分**，主循环只从它那里拿「自上次以来的平均角速度 × 时长」。

`reset_imu` 里 `reset_yaw=False` 是融合模式的关键开关：

```python
def reset_imu(board, imu_state, reset_yaw=True):
    tracker = imu_state.get('tracker')
    if tracker is None:
        return
    tracker.calibrate(0.5, settle=IMU_SETTLE_S)   # 重标零漂（传感器属性，OK）
    if reset_yaw:
        tracker.reset()                            # 清零航向（融合模式下必须 False）
```

| `STRIDE_SCALE` | 0.95 | 步幅缩放（0.946 短、0.96 过，0.95 折中） |
| `--fusion` | `lane` | 融合算法：`lane` 旧版稳定 / `reference` B 方案试验 |
| `--fusion-head-deadzone` | 1.0 | 航向死区（调大到 2 可避免「修航向修出外偏」） |
| `--fusion-cross-deadzone` | 8.0 | 横向死区（调大到 20 可少发横移、少踢航向） |

## 十一、一句话总结整个数据流

```
JSON 路线动作序列
  └─ forward/back ──► 累加 pending_forward，遇非直行动作才一次性走掉
        └─ move_straight_fusion（100mm 小块循环）
             ├─ 相机 detector() → 像素 cx → fusion.update_bearing()  写状态
             ├─ ctrl.decide(e, cross) → 先航向后横向                   定动作
             ├─ ik.turn_* / left/right_move / go_forward               执行
             └─ tracker.since_last() → fusion.predict(Δθ, ds)         推状态
  └─ turn_left/right ──► imu_turn（IMU 闭环）→ feed_turn_to_fusion（喂残差）→ reset_imu(reset_yaw=False)
  └─ pick/place ──► 固定脉宽夹取/放下 → fusion.reset()（方块被抓走/放下，参照失效）
```

**核心思想就三句**：

1. **相机写状态，IMU 管执行**——一个不归零的 `(e, cross)` 是唯一交流通道。
2. **先航向后横向**——航向误差是横向误差的因，因不除不动果。
3. **转弯只喂残差、状态永不 reset**——reset 只是把误差搬进真实姿态，不是消灭误差。
