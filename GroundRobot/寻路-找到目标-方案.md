# 寻路算法 · 第 1 步：找到目标

> 目标阶段：先用红/绿/蓝/黄方块调试；最终换成豆荚上的豆荚螟幼虫。
> 本文只讲「怎么找到目标、舵机怎么配合」，不写具体业务代码。对应本地实现：
> `GroundRobot/Code/agcs_lib/search.py`。

## 1. 这一步要解决的问题

机器人不知道目标在哪里时，需要通过云台 + 六足身体，把摄像头扫到能看见目标，
并确认「这确实是一个目标」，然后把目标中心交给下一步「对准/逼近」。

这一步输出统一成：

```python
result = {
    "center": (cx, cy),   # 画面像素中心
    "area": area,         # 轮廓面积（像素）
    "radius": radius,     # 最小外接圆半径
}
```

找不到时输出 `None`。

## 2. 用什么识别器

第一阶段先用：

1. **颜色阈值（LAB）**：从 `config/lab_config.yaml` 读当前颜色的 LAB 上下界。
2. **轮廓面积/形状过滤**：只保留最大轮廓，面积小于 `min_area` 直接忽略。

接口保持一个函数：

```python
def detect(frame) -> dict | None:
    ...
```

以后换成 YOLO 时，只需要这个函数内部改，寻路逻辑不用动。

## 3. 舵机和“看的方向”

机械臂摄像头只由两个舵机决定观察方向：

| 舵机 | 作用 | 脉宽范围 | 中间/起始值 |
|---|---|---|---|
| 21 | 水平左右转 | 0 ~ 1000 | 500（朝前） |
| 24 | 相机俯仰 | 0 ~ 1000 | 260（搜索起始） |

规则：

- **搜索阶段**：21 和 24 交替变化，一个时刻只让一个轴动。
- **每次转动后**：先等 `settle_ms` 让画面稳定，再取一帧检测。
- **找到后**：用 PID 让两个舵机把目标锁到画面中心；但目标已经接近中心时
  **不再更新 PID**，避免过冲把目标追出画面。

## 4. 扫描顺序（怎么“找一圈”）

1. 先恢复官方初始位 `(21=500, 24=260)`，不做额外调整。
2. 复位位置先看一眼；没找到，才进入 24 号舵机扫描。
3. 24 号扫描：从 0 脉宽开始，每次加 200，扫到 1000（0、200、400、600、800、1000）。
4. 21 号 500 处 24 扫一遍仍没找到，就让 21 直接回 0，再按
   `0 -> 200 -> 400 -> 600 -> 800 -> 1000` 逐点扫描；每个 21 位置都做一次 24 上下扫。
5. 21 号 0~1000 也扫完仍没找到：说明目标不在附近，**不转六足**，退出检测并报告
   “目标未在附近”。

这样同时满足：

- 先竖向再横向；
- 侧面、背后目标也有机会被发现；
- 找到后立刻锁定，不继续无意义扫描。

## 5. 找到目标后的锁定

一旦某个扫描位置 `detect()` 返回目标，执行：

1. 先做 `_confirm`：连续取 5 帧，至少 2 帧目标中心在画面边缘留白范围内，
   才算确认；避免把一帧噪声当成目标。
2. 确认后启动独立跟踪线程 `ColorTracker`，复刻官方 `color_track.py` 的 PID 部分。
3. 跟踪线程持续 `detect()`，用 21/24 把目标锁到画面中心，并保存最新位置；
   主线程通过 `latest()` 拿数据，不会被检测/PID 卡住。

PID 的设定点：

```text
cx -> 320（640 宽画面的中心）
cy -> 240（480 高画面的中心）
```

死区：

```text
|cx - 320| <= 40 且 |cy - 240| <= 60  -> 不更新 PID
否则 -> 更新 PID
```

## 6. 返回给下一步的信息

`search.run()` 返回：

```python
(center, cy)
```

并保留两个现场值：

```python
searcher.x_dis  # 找到时舵机 21 的脉宽
searcher.y_dis  # 找到时舵机 24 的脉宽
```

下一步「对准/逼近」会用这些值计算“身体应该往哪个方向转”。

## 7. 参数表（这一部分需要现场标定的）

| 参数 | 当前值 | 说明 |
|---|---|---|
| `search.pan_pulses` | `[0, 200, 400, 600, 800, 1000]` | 21 水平扫描档位，从 0 开始每次 +200 |
| `search.tilt_pulses` | `[0, 200, 400, 600, 800, 1000]` | 24 俯仰扫描档位，从 0 开始每次 +200 |
| `gimbal_fetch.settle_ms` | `280` | 每次转舵机后等画面稳定的时间 |
| `gimbal_fetch.edge_margin` | `30` | 目标中心距画面边缘的最小留白 |
| `vision.min_area` | `500` | 检测器的最小目标面积 |
| `gimbal_fetch.turn_sign` | `1` | 左右方向符号，反了就改 `-1` |

> 注意：`search.tilt_pulses` 是 **24 号舵机**的俯仰档位，不是 22 号。
> 22 号是肩关节，在搜索阶段保持不动。

## 8. 流程总览

```text
START
  │
  ▼
恢复官方初始位 (500, 260)
  ├─ 复位位置找到 -> 确认 -> 启动跟踪线程 -> 交给下一步
  └─ 没找到
  ▼
21=500，24 按 0->200->400->600->800->1000 扫一遍
  ├─ 找到 -> 确认 -> 启动跟踪线程 -> 交给下一步
  └─ 没找到
       ▼
21 回 0，按 0->200->400->600->800->1000 逐点
  每个 21 位置都 24 上下扫一遍
  ├─ 找到 -> 确认 -> 启动跟踪线程 -> 交给下一步
  └─ 没找到
       ▼
21 号 0~1000 也扫完仍没找到
  -> 不转六足，报告“目标未在附近”，返回 None
```

## 9. 待现场确认

- `tilt_pulses` 是否能让 24 覆盖从脚下到略抬头；
- `pan_pulses` 在 0/1000 时会不会打到机械结构；
- `settle_ms` 是否够稳，图像有没有拖影；
- 红/绿/蓝/黄四色的 LAB 阈值是否都稳；
- 找到目标后 PID 死区是否需要调。
