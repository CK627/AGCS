## 附：YOLO 重训教程

目标：让 `models/best.onnx` 能稳定认出机器人视角下的虫子。

### 第一步：采集训练数据（欠拟合的关键，别省）

**必须用机器人自己的彩色相机拍**（Astra Pro 彩色 `/dev/video0`），因为部署时看到的就是这个视角。

1. 在机器人上跑一个取帧脚本（或直接用 2.py 的推流画面截帧），把虫子放到机器人实际会看到的各种姿态下，多拍：
   - **角度**：正面 / 侧面 / 俯视 / 斜着，越多样越好；
   - **距离**：近 / 中 / 远（重点覆盖夹取时会出现的距离）；
   - **光照**：不同亮度、有无阴影；
   - **背景**：不同地面/台面。
2. 样本量：**几百张起步**（欠拟合就是样本太少或太单一）。
3. 用标注工具（LabelImg 之类）逐张框出虫子，导出 **YOLO txt 格式**：
   - 每张图一个同名 txt：`class_id cx cy w h`（cx/cy/w/h 都是 0~1 归一化）。
   - 类别编号用 `0`（即 `fake bug`）。

最终目录结构：

```
fake bug_raw_frames/
  images/  *.jpg
  labels/  *.txt   （与图片同名）
```

### 第二步：划分数据集（在 Mac 上，YOLOModel/ 目录）

```bash
cd /Users/jj/Documents/MyCode/AGCS/YOLOModel/Dashboard/Code
python3 split_fake_bug.py "fake bug_raw_frames" "datasets/fake_bug_v2"
```

脚本会自动按 60/20/20 分 train/val/test，把类别编号改成 0，并生成 `data.yaml`。

### 第三步：训练

```bash
python3 train.py \
  --data datasets/fake_bug_v2/data.yaml \
  --model yolov8n.pt \
  --epochs 200 \          # 欠拟合就把轮数拉高（默认 100）
  --name fake_bug_v2
```

- `--device 0`（GPU）或 `--device cpu`。
- 训练完模型在 `runs/fake_bug_v2/weights/best.pt`。

### 第四步：导出 ONNX

```bash
python3 -c "from ultralytics import YOLO; YOLO('runs/fake_bug_v2/weights/best.pt').export(format='onnx', imgsz=640)"
# 生成 runs/fake_bug_v2/weights/best.onnx
```

### 第五步：部署到机器人

```bash
scp runs/fake_bug_v2/weights/best.onnx pi@raspberrypi.local:/home/pi/spiderpi/models/best.onnx
```

然后在机器人上重跑 `python3 2.py --conf 0.4` 看检测框是否稳定框住虫子。

### 欠拟合的排查要点

| 现象 | 原因 | 对策 |
|---|---|---|
| 置信度低、乱跳 | 样本少 / 训练不充分 | 加样本、加 epoch |
| 只对某个角度有效，别的角度检测不到 | 样本角度单一 | 补其它角度的样本 |
| 出小噪点框（13×12 这种） | 训练样本里虫子太小/太少 | 补近距离大目标样本 |
| 机器人上检测不到、本地图能检测到 | 机器人视角/光照没进训练集 | 用机器人相机补采数据 |
