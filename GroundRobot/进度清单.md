## 3. 关键硬件事实（重要，别踩坑）

- 机械臂初始位（官方默认，用户确认过的正确位）：`21:500, 22:705, 23:90, 24:330, 25:700`
- 关节编号：`21`=底座横转、`22`=肩、`23`=肘、`24`=腕俯仰（相机装这里）、`25`=夹爪
- 摄像头 / 机械臂均已物理重装、方向正：`camera_rotate: 0`、`flip_servos: []`
- **逆运动学检测位** `setPitchRangeMoving((0,15,5), -90, -90)` 解出来是 `{21:500, 22:439, 23:80, 24:231}`，
  和上面的初始位不一致（22 差很多）——**夹取用 IK，复位用固定初始位，别混**
- `board.bus_servo_read_position()` 本机扩展板**只能写、不能读**物理脉宽
- **IMU 只有陀螺仪没有磁力计**，yaw 是 gz 按 dt 积分出来的相对值，会缓慢漂移 →
  长路线必须「每转一次弯就 `reset_imu()` 重标零漂 + yaw 归零」，误差不跨段传播
- 超声波近距离读数乱跳（-1、突跳几十 cm），**不可作主距离**，只做避障；主距离用深度相机或面积估距

### 深度相机（Astra Pro）—— 高度问题的解法

- 机器人上 `/home/pi/orbbec_sdk/` 是**自包含 OpenNI2 运行时**（配套 `libOpenNI2.so` + `liborbbec.so`），
  `agcs_lib/depth.py` 用 ctypes 直调；**系统 apt 装的 OpenNI2 不配套，枚举不到设备**
- **深度**走 OpenNI2（USB `2bc5:0403`），单位 mm
- **彩色**走 OpenCV `/dev/video0`：彩色设备 `2bc5:0501` 被内核 uvcvideo 占用，OpenNI2 的 `SENSOR_COLOR`
  会超时读不到帧，**不要走 `depth.read_color()`**
- 点云坐标约定：相机系 `X 右 / Y 上 / Z 前`（mm）；机器人系 2D `x 右 / y 前`（mm），
  绕竖直轴转 `φ = (500 - pan) * 90 / 400`（21 号舵机 500=正前、900=左90°、100=右90°）

## 7. 当前卡点 & 进行中 ⚠️

### 7.1 拔起脉宽现场坐实（还没坐实）

第一次夹取后要把目标从地里/网里**拔起来**，动的是 **22 号「肩」**（不是 23 号肘）。
历史上两次尝试（`705→600` 和 `23 号 200`）方向都反了，夹住之后反而把目标往下压。

**方向规律（有一条现场证据）**：22 的复位脉宽是 705，**比 705 大才是上抬**。
证据是 `785 = 705+80` 那次现场试出来「抬得太高」——说明 785 确实是在往上抬。

**当前代码里是 `PULL_UP_22 = 400`，但这个值从来没被执行过**：2026-09-15 那次跑到
「机械臂微调」提示就 Ctrl-C 退出了（日志结尾是 `arm> ^C用户中断，已退出`），
夹爪没闭合，`arm_fine_tune` 没走到拔起那几行。

⚠️ 按上面的规律，**400 < 705，方向是往下压**——正是历史上反复踩的那个坑；
而且 400 很接近路线 JSON 里的夹取位 `22:395`，可能根本不动。**再跑之前先试
705~785 之间**（如 `--pull-up 745`，比 785 抬得少一点），不要直接用 400。

两个脚本都留了 `--pull-up N`，**幅度不合适直接命令行试值，不用改代码**。

## 8. 用户反复强调的算法原则（别违背）

- **不硬编码距离 / 步数 / 固定夹取点**，要闭环、按实时画面自动调整
- **检测到颜色就锁定，不转圈**；不居中 / 不正就主动调整，不要 skip
- **夹取前先看一眼距离**；目标略超可及范围就前进微调，不轻易放弃定点夹取
- **高处目标要有保底**（体态升降 + 抬头检测）
- 官方 `block_fetch.py` / `intelligent_fetch.py` / `color_track.py` 是可靠参考

> 注意 §2.5 那两个脚本是**固定路线 + 固定脉宽**的比赛演示，和上面这条原则是两套东西：
> 原则针对自主寻路/夹取（`agcs_lib/search.py` + 深度 3D 抓取），别拿原则去改比赛脚本的路线设计。
