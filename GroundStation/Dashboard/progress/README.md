# 研发进度流程图（独立网页 / 独立端口）

把地面站中枢的研发进度画成**流程图**（含流动动画），单独一个网页、单独一个端口，
但和中枢**由同一套启动脚本一起启停 / 重启**。

- 中枢仪表盘：`http://localhost:20000`（数据采集 + 四个面板）
- 研发进度流程图：`http://localhost:20010`（本服务）

## 它做什么

```
中枢（GroundStation/Dashboard，20000）
   ├─ 采集无人机 / 机器人 / 服务器 / YOLO 数据
   ├─ 维护研发进度状态（data/progress.json，含自动触发）
   └─ GET /api/progress/flow  ← 每步的 done / active / pending + 模块进度
              ↑
本服务（progress/app.py，20010）
   ├─ GET /                → 流程图页面（含动画）
   └─ GET /api/progress/flow → 代理中枢的同名接口（中枢挂了显示"中枢未连接"）
```

进度数据只有中枢有（触发逻辑都在它那儿），所以这里只做**代理 + 画图**，
不在本地存一份，避免两边不一致。

## 启动（推荐：用启动脚本）

```bash
# 一起启动（中枢 20000 + 进度流程图 20010）
bash GroundStation/Dashboard/scripts/macOS/start.sh start      # macOS
bash GroundStation/Dashboard/scripts/Linux/start.sh start      # Linux
GroundStation\Dashboard\scripts\Windows\start.bat start        # Windows

# 一起看状态 / 停止 / 重启
... start.sh status
... start.sh stop
... start.sh restart
```

想换端口：`start.sh start 8080 8081`（第 1 个是中枢，第 2 个是进度流程图）。
两个端口也会写进 `data/server.port` / `data/progress.port`，状态查询用得到。

## 单独运行（调试用）

```bash
cd GroundStation/Dashboard/progress
python -m pip install -r requirements.txt
python app.py                                  # 0.0.0.0:20010，中枢取 127.0.0.1:20000
python app.py --port 20010 --hub http://192.168.124.7:20000
```

## 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/` | GET | 流程图页面 |
| `/api/progress/flow` | GET | 代理中枢进度接口；中枢不可达时返回空结构 + `hub_online:false` |
| `/status` | GET | 轻量健康检查（端口 / 中枢地址 / 运行时长） |

## 版面：照新版设计稿，**横版**（自左向右读，给宽屏显示器用）

新版《研发工单》设计稿是横版，这里逐字照做：左边系统名（圆角矩形）→ 第一阶段（手动链路 4 框）
→ 第二阶段（四个模块横排）→ 各模块下方竖排步骤 → 底部综合展示。

```
  ╭──────────────╮   ┌────────────────────┐   ┌──────────────────────────┐
  │ 空地协同农作  │──▶│ 第一阶段验证可行性   │──▶│ 第二阶段研发自动化系统    │
  │ 虫害自动巡检  │   └─────────┬──────────┘   └──┬────────────┬──────────┘
  │   捕获系统    │             │                 │            │ 3自动捕获虫害
  ╰──────────────╯             │                 ▼            ▼
        （系统名＝水源）           │        ┌──────────┐   ┌──────────┐   ┌──────────┐
                               │        │无人机自动巡检│──▶│ 中枢互通  │◀──│ 模型训练  │
                               │        └─────┬────┘   └────┬─────┘   └────┬─────┘
                               │              │  1自动巡检虫害 │  2识别虫害     │ 3提供模型(虚线)
                               │              ▼             ▼             ▼
                               │        （各 5 行步骤） （5 行 / 6 步） （各 5 行步骤）
                               │              │             │             │
                               └──────────────┴──────┬──────┴─────────────┘
                                                     ▼
                                    综合展示：自动巡检与捕获
```

- **名称 / 步骤文字逐字照设计稿**：写在 `progress.js` 顶部的 `FLOW_STEPS`（每个模块按
  "行 → 框" 组织）、`MOD_LINES`（模块标题断行）、`MANUAL`（第一阶段 4 框）里。
  中枢互通第 3 行是两个并排框（`网络配置` ｜ `部署环境`），`共研航线` 第 2 行单独一格、与无人机模块一致。
- **顶部主干**：系统名方框（圆角矩形，和别的框一致）→ 第一阶段，再一条长横管接到第二阶段。
- **第二阶段分水**：第二阶段底部一根竖管下到分支横管，横管横贯四列，
  再各自竖直落进四个模块框（四个模块走法一致、不再各自单独从主干叉出来）。
- **模块之间的标注连线**（照设计稿）：`模型训练 → 中枢互通`＝**2识别虫害**；
  `模型训练 ┈→ 机器人自动捕获`＝**3提供模型**；`中枢互通 → 机器人自动捕获`＝**3自动捕获虫害**；
  `无人机自动巡检 ┈→ 模型训练`（虚线数据线）＝**1自动巡检虫害**。
  另有 `无人机自动巡检 → 中枢互通` 一条无标注的实线箭头。
- **两类连线**：
  ① **水路＝管道**（管壁 + 管腔 + 一条亮边一条暗边 + 管内水体 + 流动光带，靠水流表达方向、
     **不画箭头**），会跟着进度通水 / 变色；
  ② **提示连线＝细线**（2识别虫害 / 3提供模型 / 3自动捕获虫害 / 1自动巡检虫害 四条；
     其中「1自动巡检虫害」挂在那条 `无人机自动巡检 ┈虚线→ 模型训练` 的数据线上，
     「3自动捕获虫害」是 中枢互通 → 机器人自动捕获，走标题行上方那条高线）—— 它们表达的是"信息怎么走"的提示、
     **不是水管**，所以只画细线 + 末端小箭头（数据类用虚线），不参与通水动画、也不随进度变色。
     注：四个模块标题框**等高**，所以"无人机 → 模型训练"这条不像设计稿那样平着穿过去，
     而是走**标题行下方的拐折线**（下行 → 右拐 → 上折进模型训练框底），保证两端都接上框。
- **没走到的管子是干管（pending）**：进度到达时才从源头往末端"慢慢灌水"（水头推进的过渡
  动画），灌满后光带再持续扫过；灌水 / 光带周期按管道实际长度归一化，长短管流速看起来一致。
- **模块内部是"一行一行往下走"**：模块框 → 第 1 行步骤 → 第 2 行 …… 步骤之间一根竖管；
  中枢互通第 2 行是两个并排框，管子会"一分二 / 二合一"（中缝下、左右分）。
- **步骤组的圆角框只圈"步骤框"**：模块标题框在框**外面**（照设计稿），框是**实线**圆角矩形，
  上下各留 18px 内边距；第一阶段的手动链路同理（框里只有 4 个步骤框，没有标题）。
- **第一阶段那列与四个模块组等高**：手动链路容器上下和模块组齐平，
  四个框把剩余高度均分（框自动放大，文字也放大到 18px），左边不会比右边矮一截。
- **底部四路各自接入**（照设计稿，不用汇流总管）：每个模块各有一根管往下走 ——
  中间两列直接落进「综合展示」框顶；左边那列下到底后**右拐进框的左口**；
  右边那列下到底后**左拐进框的右口**。四条管各自跟自己的模块状态变色。
- **模块框按状态变色**：全部完成=绿、进行中/部分完成=青、未开始=灰。
- 整张图由 `fitFlow()` 按可用宽高**取较小缩放比**铺开，**一屏完整显示、比例不变形**；
  窗口变化自动重算，点「⛶ 全屏」会再算一次。竖屏（缩放比 < 0.5，比如把本页拖到竖显示器上）
  会自动改成**按宽铺满 + 纵向滚动**。
- **画布比例是照着 flow-wrap 的可用区域定的**（`LV.H = 950`，宽高比 ≈ 1920:950）：
  按宽度缩放后纵向也正好铺满，图下面不会留一大片空白。整体想再高/再矮，
  改 `stepH` / `stepGap` / `LV.H` 即可（手动链路与四个模块组会自动跟着对齐）。

> 步骤数和中枢任务清单是**一一对应**的：第一阶段 4 步、无人机 5 步、模型训练 5 步、
> 中枢互通 6 步（页面上排成 5 行，其中一行两个框）、机器人 5 步 —— 共 25 步。
> 任务清单的**勾选入口在中枢页面**（右上角「任务清单」），勾选直接写回中枢进度，
> 本页面每 2 秒同步显示结果。
## 页面上的动画都是什么意思

| 元素 | 含义 |
|------|------|
| 干管（只有管壁，没有水） | 还没走到这一步（pending） |
| 水从源头慢慢灌满整根管子 | 状态刚变化时的过渡（不是瞬间亮起） |
| 管里有青色水 + 光带流动 | 正在进行的链路（live） |
| 满管绿色连续水流 | 已完成的链路 / 结构管路（done，不再分段） |
| 绿色方框 | 该步骤已完成 |
| 青色方框 | 该步骤正在进行 |
| 灰色方框 | 未开始 |

页面每 2 秒向中枢取一次进度；**整张 SVG 只建一次，之后只改 class / 文本**，
不重绘 DOM，所以连线流动、灌水、脉冲动画都不会被打断。

> 页面骨架、样式、脚本已拆成三个文件：`index.html`（结构）、`progress.css`（样式与
> 全部动画规则）、`progress.js`（版面绘制 + 进度状态映射），由 `app.py` 静态路由提供。

## 端口与配置

- 进度页端口：`data/config.yaml` 里 `dashboard.progress_port`（默认 20010），
  也能在**中枢页面的「⚙ 配置」**里改。
- 中枢地址：默认 `http://127.0.0.1:20000`，按 `--hub` 参数 / `HUB_URL` 环境变量覆盖；
  启动脚本会自动带上中枢的真实端口。
