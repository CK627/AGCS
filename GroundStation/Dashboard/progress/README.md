# 研发进度流程图（独立网页 / 独立端口）

把地面站中枢的研发进度画成**流程图**（含流动动画），单独一个网页、单独一个端口，
但和中枢**由同一套启动脚本一起启停 / 重启**。

- 中枢仪表盘：`http://localhost:20000`（数据采集 + 四个面板）
- 研发进度流程图：`http://localhost:20010`（本服务）

## 它做什么

```
中枢（GroundStation/Dashboard，20000）
   ├─ 采集无人机 / 机器人 / 服务器 / YOLO 数据
   ├─ 维护研发进度状态（data/progress.json，含自动触发）
   └─ GET /api/progress/flow  ← 每步的 done / active / pending + 模块进度
              ↑
本服务（progress/app.py，20010）
   ├─ GET /                → 流程图页面（含动画）
   └─ GET /api/progress/flow → 代理中枢的同名接口（中枢挂了显示"中枢未连接"）
```

进度数据只有中枢有（触发逻辑都在它那儿），所以这里只做**代理 + 画图**，
不在本地存一份，避免两边不一致。

## 启动（推荐：用启动脚本）

```bash
# 一起启动（中枢 20000 + 进度流程图 20010）
bash GroundStation/Dashboard/scripts/macOS/start.sh start      # macOS
bash GroundStation/Dashboard/scripts/Linux/start.sh start      # Linux
GroundStation\Dashboard\scripts\Windows\start.bat start        # Windows

# 一起看状态 / 停止 / 重启
... start.sh status
... start.sh stop
... start.sh restart
```

想换端口：`start.sh start 8080 8081`（第 1 个是中枢，第 2 个是进度流程图）。
两个端口也会写进 `data/server.port` / `data/progress.port`，状态查询用得到。

## 单独运行（调试用）

```bash
cd GroundStation/Dashboard/progress
python -m pip install -r requirements.txt
python app.py                                  # 0.0.0.0:20010，中枢取 127.0.0.1:20000
python app.py --port 20010 --hub http://192.168.124.7:20000
```

## 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/` | GET | 流程图页面 |
| `/api/progress/flow` | GET | 代理中枢进度接口；中枢不可达时返回空结构 + `hub_online:false` |
| `/status` | GET | 轻量健康检查（端口 / 中枢地址 / 运行时长） |

## 版面：照《研发工单》原图，但排成**竖版**（给竖屏副显示器用）

原《研发工单》图是横版（四个模块左右一字排开）。挂到**竖屏副显示器**上时横版会缩得很小，
所以这里把同一条流水线**竖过来**：节点、先后顺序、"互通"关系一个都不变，只是自上而下走。

```
                          《空地协同农作害虫AI视觉自动巡检捕获系统》研发工单
                                            │
                                  第一阶段验证可行性
                                            │
                       ╭────────────────────────────────────╮
                       │        手动操控无人机巡检            │
                       │                │                   │
                       │        人工传输巡检信息              │
                       │                │                   │
                       │        手动操控机器人捕获            │
                       ╰────────────────────────────────────╯
                                            │
        ┌── 主管道 ─────────────── 第二阶段研发自动化系统
        ┆
        ┆          ╭──────────────────────────────────────────╮
        ┆          │              ┌──────────┐     进度 0%     │
        ┆          │              │  无人机   │                │
        ┆  支管 ─→ │              │ 自动巡检  │                │
        ┆          │              └────┬─────┘                │
        ┆          │     ┌───────────────────┴──────────┐     │
        ┆          │     │        （分水器）              │     │
        ┆          │  ┌──┴─────┐  ┌──┴──────┐  ┌──┴────┐    │
        ┆          │  │自动直线飞行│→│S型提高巡检效率│→│多机共检：修理飞机│
        ┆          │  └────────┘  └─────────┘  └───────┘    │
        ┆          ╰──────────────────────────────────────────╯
        ┆          ╭──────────────────────────────────────────╮
        ┆  支管 ─→ │  模型训练：拍照采样、数据标注│欠拟合│正常│过拟合 │
        ┆          ╰──────────────────────────────────────────╯
        ┆          ╭──────────────────────────────────────────╮
        ┆  支管 ─→ │  中枢互通：网络连线│网络配置│架设平台         │
        ┆          │            安装系统│配置环境│部署软件       │
        ┆          ╰──────────────────────────────────────────╯
        ┆          ╭──────────────────────────────────────────╮
        ┆  支管 ─→ │  机器人自动捕获：开发稳压电路板│视觉追踪│自主寻路│自动抓取 │
        ┆          ╰──────────────────────────────────────────╯
        ┆
        └──────────────────→  综合展示：自动巡检与捕获
```

> **主管道走左侧**：第二阶段从左边接出一条主管道，一路往下，四个模块各自从主管道
> 分一路支管进来（并行推进、互不串联 —— 原图里"互通"是这个意思，不是"上一个模块的
> 产物流进下一个模块"），主管道走到底汇进「综合展示」。主管道画得比支管粗一号。

- **文字逐字照抄原图**：模块名、每一步的名字、底部"综合展示"全部原样（含原图的
  `《空地协同农作害虫AI视觉自动巡检捕获系统》`）。文字写在页面顶部的
  `FLOW_STEPS` / `MOD_LINES` 常量里，要改直接改这两个常量。
- **连线一律是"管道"**（`flPipe`）：管壁 + 深色管腔 + 一条亮边一条暗边（圆柱感）
  + 管内水体 + 沿管子扫过的流动光带。**没走到的管子是干管（pending）**，进度到达时
  才从源头往末端"慢慢灌水"（水头推进的过渡动画），灌满后光带再持续扫过；
  灌水/光带周期都按管道实际长度归一化，所以长管和短管的流速看起来一致。
  **管口一律方口**（静态水体不用圆头），端点全部藏在框/横管后面 —— 管子不露头、不凸出。
  画图顺序是"先管后框"：支管/落管/滴管先画，模块框和步骤框后画，正好把管口盖住。
- **每个模块是一条"分流 → 流过 → 合并"的旁路**：主管道分一路支管进模块框，
  到模块框上方一分二、贴着框两侧流下、框底二合一（和手动链路一致），
  再经顶部分水器把水分到各列；每个小目标框同样"一分二、贴框两侧流下、框底二合一"，
  底部收集管从右往左汇流，最后并回主管道。中枢互通是两行：水从最左端竖管下行，
  两行都从左往右推进，每列同样是"一分二、贴框流下、二合一"；第一行底部的收集管
  同时充当第二行的分水器（中间横管），第二行底部再收集、汇流回主管道。
- **手动链路同样"一分二、二合一"**：一根管到目标框上方分成左右两路，贴着目标框
  两侧流下，框底汇合成一根再去下一个目标；分流时目标框按状态过渡亮起（填充/描边
  渐变动画，进行中还带呼吸脉冲）。
- **不画箭头**：水流本身已经表达了方向，箭头在管道上属于多余装饰。
- **每个模块框下面挂一个"分水器"**：一条总管从模块框下来，接一根横管，
  再往每一列滴一根短管 —— 一眼能看出"这个模块下面挂了几件事"。
  中枢互通是 2 行（原图就是 2×3），分水器会往下再分一层。
- **步骤列用竖排文字**（一个汉字一行），照原图；方框左侧一条竖进度条：
  已完成=满格、进行中=60%、未开始=空。
- **模块框按状态变色**：全部完成=绿、进行中/部分完成=青、未开始=灰；
  状态切换带填充/描边过渡动画，虚线框右上角显示"进度 xx%"。
- 整张图由 `fitFlow()` 按可用宽高**取较小缩放比**铺开，
  所以**一屏完整显示、比例不变形**，也不会因滚动条/文字换行反复抖动；
  窗口变化自动重算，点「⛶ 全屏」会再算一次（全屏能拿到更多高度，图更大）。
  横屏（比如在中枢的 1920×1080 上打开）时按高缩会小到看不清，
  这时自动改成**按宽铺满 + 纵向滚动**。
- 竖排框高度会跟着**最长的步骤名**自动调（`44 + 最长字数×13.6`），
  文字加长了不用改代码。

> 原图里每个模块是 3/4/6 列，中枢的任务清单是每个模块 6 步。
> 页面按 **模块完成比例 × 列数** 把状态等比铺到各列上（做几步，前面几列就亮几步）。
> 任务清单的**勾选入口在中枢页面**（右上角「✅ 任务清单」，在「🧭 进度流程」左边），
> 勾选直接写回中枢进度，本页面每 2 秒同步显示结果。

## 页面上的动画都是什么意思

| 元素 | 含义 |
|------|------|
| 干管（只有管壁，没有水） | 还没走到这一步（pending） |
| 水从源头慢慢灌满整根管子 | 状态刚变化时的过渡（不是瞬间亮起） |
| 管里有青色水 + 光带流动 | 正在进行的链路（live） |
| 满管绿色连续水流 | 已完成的链路 / 结构管路（done，不再分段） |
| 青色光带扫过一段 | 阶段/模块刚解锁时的扫描提示（中枢互通为从左到右，其余自上而下） |
| 绿色方框 | 该步骤已完成 |
| 青色方框 | 该步骤正在进行 |
| 灰色方框 | 未开始 |

页面每 2 秒向中枢取一次进度；**整张 SVG 只建一次，之后只改 class / 文本**，
不重绘 DOM，所以连线流动、灌水、脉冲动画都不会被打断。

> 页面骨架、样式、脚本已拆成三个文件：`index.html`（结构）、`progress.css`（样式与
> 全部动画规则）、`progress.js`（版面绘制 + 进度状态映射），由 `app.py` 静态路由提供。

## 端口与配置

- 进度页端口：`data/config.yaml` 里 `dashboard.progress_port`（默认 20010），
  也能在**中枢页面的「⚙ 配置」**里改。
- 中枢地址：默认 `http://127.0.0.1:20000`，按 `--hub` 参数 / `HUB_URL` 环境变量覆盖；
  启动脚本会自动带上中枢的真实端口。
