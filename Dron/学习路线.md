### 4.1 与 README 总目标的对应关系

学习路线不是孤立地学无人机，每一步都要**落在 README 的验收标准上**，
配合其他三人完成总目标：

| README 验收标准（4.5 节） | 对应模块 | 谁配合 |
|---------------------------|----------|--------|
| 无人机自主飞行：可按预设航线完成巡检 | 模块 4 航线与自主飞行 | 杨梦享（任务调度） |
| MAVLink 通信：地面站实时获取位置/姿态 | 模块 3 电脑互通（pymavlink 直接打通） | 杨梦享（pymavlink/MAVLink） |
| 视频传输：视频流延迟 <200ms | 模块 2 数传图传 + 模块 5 机载视觉 | 谢啸（网络架构） |
| YOLO 检测：可识别豆荚螟危害特征 | 模块 6 YOLO 检测 | 谢啸（模型训练） |
| 完整协同：侦察→定位→抓捕全流程 <5分钟 | 模块 7 协同验证 | 全体（马晨轩抓捕、杨梦享调度） |

开始前先读懂 README「四、完整协同流程」的五个步骤，明确你的环节：
无人机起飞巡检 → 地面站 YOLO 检测 → 坐标下发 → 机器人导航 → 机械臂抓捕。
你的产出（画面、坐标、状态）是这条链路的第一环。

## 5. 第一阶段合并：人工视觉追踪

**目标**：先用"人眼"完成侦察闭环，理解整个链路，再谈自动化。

1. 定点飞行 + 地面站实时画面，练习追踪地面目标
2. 用 QGC 航线让无人机按固定路线巡检，人工在画面上找目标
3. 记录：飞行高度、速度、画面效果对识别的影响

**验收**：能操控无人机发现目标并口头描述位置（相对画面中心/航点）。

## 6. 第二阶段合并：无人机视觉识别

**目标**：把"人眼"换成"算法"，画面回传后 YOLO 自动检测。

1. 用 GStreamer/OpenCV 把 RTSP 视频流接入程序
2. 部署 YOLO 模型（先用预训练模型，再换谢啸训练的豆荚模型）
3. 检测结果叠加 GPS/光流位置 → 计算目标坐标（与杨梦享对接）

**验收**：无人机巡检画面中，程序能稳定框出目标并给出坐标数据。

## 7. 第三阶段：验证并提升识别稳定性

**目标**：从"能识别"到"稳定识别"。

### 7.1 与谢啸的协作闭环

```
你（现场飞行采集/验证）──▶ 谢啸（标注/训练）──▶ 你（部署验证）
          ▲                                         │
          └────────── 识别失败案例反馈 ──────────────┘
```

1. 不同光照/高度/角度下采集视频，整理成数据集
2. 谢啸训练后你部署验证，记录误检/漏检案例再反馈
3. 验证悬停精度、视频延迟对识别的影响（目标：延迟 <200ms）

**验收**：模拟毛豆田场景巡检，识别稳定，误检率明显下降。
